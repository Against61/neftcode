# План усиления конкурсного решения

| № | Направление | Реализованное состояние | Конкурсный статус |
|---:|---|---|---|
| 1 | Прогноз качества 15–180 мин | HGB против последнего допустимого ЛИМС; calibration и 2024Q4 holdout; диапазон неопределённости | Готов, 5/5 горизонтов прошли gate |
| 2 | Прогноз P8/T11/F19 | Модель сравнивается с `NO_CHANGE`; F19 выбран на 5 горизонтах, P8/T11 оставлены без изменения | Готов как честный частичный результат, общий gate отклонён 5/15 |
| 3 | Модель отклика | Есть сценарная модель и строгий pipeline command→execution→проба→лаг→holdout | Архитектура готова; причинная калибровка ждёт реальных команд |
| 4 | Исторические аналоги | Пять robust-scaled аналогов с временем, расстоянием, качеством и controls | Готов как диагностический контекст |
| 5 | Модель АВТ | Пересчитывает выходы и свойства при изменении сырья и режима | Готова как проверяемая инженерная модель |
| 6 | Оптимизатор ГТ | Сравнивает планы P8/T11/F19 с `NO_CHANGE`, проверяется независимым gate | Готов как модельный оптимизатор |
| 7 | Оптимизатор смешения | Динамические доли ГТ/чистого/тяжёлого компонента/присадки и материальный баланс каждого шага | Готов |
| 8 | Неопределённость | Диапазоны прогноза и сценарные миры; рекомендация блокируется, если ограничение нарушается в части диапазона | Готов |
| 9 | Временная доступность | ЛИМС target по sample time; online только по отдельной доступности; ПАК excluded | Готов |
| 10 | Эталон агента | 8 development + 5 heldout сценариев через настоящий MCP, evaluator agent trace | Готов; реальный LLM trace запускается отдельно |
| 11 | Временной holdout | Selection/model hashes фиксируются до открытия 2024Q4 | Готов для исторического ML-компонента |
| 12 | Обратная связь | Append-only API сохраняет issue, execution, решение и будущие пробы; pipeline пересчитывает readiness | Контур готов, реальных будущих записей пока 0 |

Конкурсный образец можно развернуть без недоступного журнала реальных команд.
Исторический прогноз и аналоги усиливают объяснение, а сценарный оптимизатор
формирует план. Между ними сохранена граница: исторически типичные controls не
подменяют оптимальные команды. Реальные command→outcome пары нужны для
промышленной причинной калибровки, но не для запуска конкурсной архитектуры.
