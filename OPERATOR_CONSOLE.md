# Единая локальная консоль

Консоль объединяет два разных результата:

1. read-only исторический срез из HT CSV и ЛИМС XLSX;
2. расчёт собственной модели по полному набору явно заданных параметров.

Связь ограничена одним полем: `feed_t95` можно взять из допустимой пробы
ЛИМС, если пользователь отдельно включил консервативное правило sample+4ч.
Фактическое время публикации при этом остаётся неизвестным. HT P8/T11/F19
показываются только как контекст, ПАК исключён. Результат помечается
`historical_recommendation=false` и `industrial_command=false`.

## Запуск после клонирования

Нужны Python 3.12, файл `242000_tags.csv` и книга ЛИМС. Они могут лежать
рядом с репозиторием или в отдельном архивном каталоге. Внешняя модель и сеть
для UI не требуются.

Одна команда после установки зависимостей создаёт локальную конфигурацию,
проверяет Python, пути, SHA-256, формат источников, строгий срез без раскрытия
ЛИМС и изолированный worker, а затем запускает сервер:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-agent.txt

python scripts/start_operator_console.py --data-root /path/to/archive
```

Откройте `http://127.0.0.1:8765`. Сервер слушает только loopback. Браузер
передаёт время среза, два флага и модельный сценарий; пути к файлам, SHA,
политика и код задаются процессу при запуске и через HTTP не меняются.

Автоопределение ищет `data/242000_tags.csv` или `242000_tags.csv` и ровно одну
книгу `ЛИМС*.xlsx` в корне архива или `data/`. При другом имени или нескольких
кандидатах укажите относительные пути явно:

```bash
python scripts/configure_local_data.py \
  --data-root /path/to/archive \
  --telemetry data/242000_tags.csv \
  --lims 'data/ЛИМС.xlsx' \
  --output history_sources.local.json
```

Генератор не копирует данные. Он проверяет, что оба файла находятся внутри
`data-root`, и записывает их относительные пути и SHA-256. Существующую
конфигурацию он не перезаписывает. Сами CSV/XLSX и `*.local.json` исключены
из публичного репозитория.

Отдельная предварительная проверка без запуска сервера:

```bash
python scripts/neft_doctor.py \
  --data-root /path/to/archive \
  --history-sources history_sources.local.json
```

Doctor возвращает ненулевой код при несовпадении SHA, неверной схеме,
нечитаемом временном окне, раскрытии ЛИМС в строгом режиме или отказе worker.
В отчёт входят только метаданные и количества, без исторических значений.

## Работа в интерфейсе

1. Выберите `as_of` и загрузите срез. Без правила4ч значения ЛИМС с неизвестной
   публикацией не раскрываются расчёту.
2. Введите все модельные параметры. Кнопка демонстрационных допущений заполняет
   учебный пример; это отдельное явное действие, числа не считаются архивными.
3. При желании включите привязку T95 ЛИМС. Для неё также нужно включить
   sample+4ч и заново загрузить срез. Если свежей допустимой пробы нет, расчёт
   откажет без ручного fallback.
4. Python проверит контракт, предел серы≤10, полную сетку неопределённости и
   независимый gate. Для каждого входа UI покажет происхождение.

Каждый вызов сохраняется в `operator-calls/<call-id>/`: аргументы, срез,
request/decision/scenario, stdout/stderr worker и манифест с SHA. Новый вызов
не переиспользует предыдущий план. HTTP-поток только принимает JSON и ожидает
изолированный дочерний процесс. Таймаут — 20 с, одновременно допускаются два
расчёта; следующий получает `RUNTIME_BUSY`. Чтение HTTP-запроса ограничено 5 с,
размер HTTP-входа — 256 КиБ;
неизвестные/дублированные поля, NaN/Infinity, защищённые периоды и подмена
путей отвергаются. `/healthz` сообщает режим, таймаут, предел параллельности
и SHA конфигурации источников.

## Агент и JSON

При том же подключении архива MCP-сервер предоставляет четыре инструмента:

- `get_refinery_contract`;
- `recommend_refinery_plan`;
- `get_refinery_history`;
- `evaluate_refinery_scenario_with_history`.

```bash
python scripts/agent_connection.py \
  --data-root /path/to/archive \
  --history-sources history_sources.local.json \
  --launch
```

Последний инструмент принимает тот же явный сценарий, запускает отдельный
дочерний Python-процесс и возвращает provenance, модельный план/отказ и пути
аудита. Агент не задаёт файловые пути и не может повысить условный результат
до исторической рекомендации. Ответ инструмента может быть передан провайдеру
внешней модели используемым MCP-клиентом; локальный браузер этого не делает.

## Проверки

```bash
python -m unittest -v \
  test_agent_tool test_decision_cycle test_expert_contracts \
  test_scenario_sensitivity test_history_adapter test_operator_console \
  test_runtime_v5
python scripts/check_history_protocol.py --output /tmp/neft-history-protocol
python scripts/check_runtime_smoke.py
```

Frozen v4: 85 unit-тестов, 10 MCP-случаев, 9 модельных сценариев
на пяти прежних срезах и точное совпадение 9/9 с прямым API. Живой UI прошёл
desktop/mobile, путь с T95 ЛИМС и отказ без правила4ч; внешних запросов и
JS-ошибок нет. Runtime v5 добавляет 4 unit-теста и CI live smoke: автоматическая
конфигурация, doctor, случайный loopback-порт, UI/health/history/evaluate,
отказ неверного JSON-контракта и три полных аудита на сгенерированных CSV/XLSX.
Это проверка интеграции, а не исторической точности модели.

## Что всё ещё вводится вручную

Архив не даёт подтверждённого отображения для `crude_sulfur`, `crude_flow`,
`feed_cn`, реальных запасов/свойств резервуаров, заказа и спецификаций.
Консоль делает эти допущения видимыми и позволяет считать сценарии, но не
превращает их в факты. Полностью автоматическая рекомендация по одним только
имеющимся файлам остаётся недоказанной до появления этих источников и
проверки модели эффекта на независимых action-outcome данных.
