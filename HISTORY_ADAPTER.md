# Адаптер исторических данных

Адаптер читает существующие HT CSV и ЛИМС XLSX, формирует состояние на `as_of`
и передаёт допустимые лабораторные наблюдения в канонический Python-цикл.
Новый импорт базы данных не нужен. Файлы остаются в локальном каталоге;
публичному репозиторию достаточно кода и синтетических тестов.

## Подключение файлов

Python 3.12 и зависимости из `requirements-cycle.txt` для CLI, из
`requirements-agent.txt` для MCP. Чтение CSV/XLSX реализовано стандартной
библиотекой; Excel, pandas и внешняя база для запуска не нужны.

Создайте конфигурацию автоматически (файлы не копируются):

```bash
python scripts/configure_local_data.py \
  --data-root /path/to/archive \
  --output history_sources.local.json
```

Или создайте `history_sources.local.json` вручную с относительными путями от
каталога данных и настоящими SHA-256 файлов (`shasum -a 256 путь-к-файлу`):

```json
{
  "schema": "history-sources-v1",
  "telemetry": {"path": "data/242000_tags.csv", "sha256": "SHA256_ФАЙЛА_CSV"},
  "lims": {"path": "lims.xlsx", "sha256": "SHA256_ФАЙЛА_XLSX"}
}
```

Имена файлов произвольны; пути и контрольные суммы должны соответствовать
источникам. Формат содержимого закреплён: CSV с `date` и короткими HT-тегами,
Excel с листом `Лист1` и зарегистрированными независимыми парами дат/значений.
Проверяются заголовки групп, показателей и единиц. При другом формате требуется
новая версия карты, а не автоматическая догадка по величинам.

```bash
python scripts/run_history_adapter.py \
  --data-root /path/to/archive \
  --sources history_sources.local.json \
  --as-of 2024-01-01T09:00:00 \
  --output output/history-strict
```

По умолчанию публикация ЛИМС неизвестна: результаты проб не входят в запрос
цикла. Для явно принятой консервативной границы из ответа эксперта:

```bash
python scripts/run_history_adapter.py \
  --data-root /path/to/archive \
  --sources history_sources.local.json \
  --as-of 2024-01-01T09:00:00 \
  --use-lims-upper-bound \
  --output output/history-upper
```

Результаты: `history.json`, `request.json`, `decision.json`, `report.html`
и `manifest.json`. Новый запуск требует нового выходного каталога. Ошибка
источника, схемы или контрольной суммы даёт `error.json`, код завершения 1
и журнал ошибки. Бизнес-отказ цикла сохраняется как штатный результат, код 0.

## Что сопоставлено

| Источник | Поле исторического состояния | Передача в цикл |
|---|---|---|
| HT P8 / T11 / F19 | Температура / расход сырья / давление ГТ | Только исторический контекст: единицы и доступность не подтверждены |
| ЛИМС CC:CD, вход ГТ, Mass.Sulfur | `ht_feed_sulfur`, % масс. × 10000 → мг/кг | Не заменяет серу нефти `crude_sulfur` |
| ЛИМС BU:BV, вход ГТ, 95%.T | `ht_feed_t95`, °C | Доступное наблюдение `feed_t95` |
| ЛИМС CQ:CR, выход ГТ, Mg.Sulfur | `ht_product_sulfur`, мг/кг | Доступное наблюдение `product_sulfur`; не входное сырьё |
| ЛИМС CO:CP и CY:CZ, выход ГТ | Выходные Т95 и цетан | Контекст; не подставляются во входные свойства |
| ПАК | Недоступен | Числа не читаются: неизвестны время доступности и исправность |

В каждой паре Excel своя дата. Адаптер не объединяет их по номеру строки и
не считает одновременные пробы одной порцией продукта. % масс. переводятся
в мг/кг только у зарегистрированной серии Mass.Sulfur; другие единицы
сопоставлены явно и проверяются по заголовкам.

## Временной контракт и ограничения

- Разрешён период 2023–2024. Перед срезом требуется полное допустимое окно
  24 ч плюс 10 мин для телеметрии. Часы общие локальные, UTC offset неизвестен.
- HT показывается до `as_of − 10 мин`: это прежнее условие просмотра истории,
  а не установленная доступность. Архивные значения не попадают в online features.
- Timestamp ЛИМС — время отбора. При включённом правиле4ч допуск возможен
  лишь после `sample + 4 ч`; `actual_publication=null`. Порог возраста пробы
  24 ч — политика демонстрации. Более поздняя, ещё недоступная проба не
  вытесняет предыдущую доступную. Плохая/дублированная последняя доступная
  проба блокирует выбор серии, без незаметного возврата к старой.
- Читаются числовые значения только в запрошенных прошлых окнах. SHA всего
  файла используется для идентичности; метаданные происхождения изменятся
  при изменении файла даже вне окна. Изменение будущих значений не меняет
  выбранные числа или поведение решения.
- CSV и каждая пара Excel должны быть отсортированы по времени. Чтение
  прекращается после верхней границы; порядок неиспользованного хвоста не
  проверяется. Дубликаты CSV отклоняются, дубликаты проб не выбираются.
- `scenario_parameters` / `--scenario scenario.json` разрешают явное задание
  заказа, горизонта, сетки и свойств/запасов резервуаров. Они помечаются как
  параметры пользователя и не считаются наблюдениями архива.

`request.json` всегда имеет `scope=historical_replay`. Без доступного входного
Т95 цикл возвращает `ABSTAIN_DATA`, при его наличии — `ABSTAIN_HISTORICAL_SCOPE`.
Историческое чтение готово; модель рекомендаций на этой истории ещё требует
обоснованной связи остальных входов и состояния ГТ. Смена scope на synthetic
не создаёт такой связи. `missing_model_fields` и `mapping_limits` показывают
конкретные пробелы; синтетический пресет автоматически не подставляется.

## Подключение агента

Пути к архиву задаёт оператор при запуске сервера. Агент передаёт только время,
флаг4ч и явные параметры задания; менять пути, период доступа, модель или
обязательные ограничения через инструмент нельзя.

```bash
python scripts/agent_connection.py \
  --data-root /path/to/archive \
  --history-sources history_sources.local.json \
  --launch
```

Без этих параметров доступны прежние два MCP-инструмента. С ними добавляются
`get_refinery_history` и `evaluate_refinery_scenario_with_history`; второй
описан в [инструкции консоли](OPERATOR_CONSOLE.md). Первый вызывается так:

```json
{"as_of": "2024-01-01T09:00:00", "use_lims_upper_bound": true}
```

Инструмент возвращает доступные наблюдения, запрос, причины отказа и пути к
доказательствам. Таймаут дочернего процесса20с, вход≤256КиБ. Вызов сохраняется
в серверном каталоге аудита, recommendation всегда null. Подключение локальное;
MCP-клиент с внешней моделью может передавать ответ инструмента её провайдеру.
Для работы CLI внешняя модель и сеть не нужны.

## Проверки

```bash
python -m unittest -v test_history_adapter test_operator_console
python scripts/check_history_protocol.py --output /tmp/neft-history-protocol
```

Синтетические тесты сами создают небольшой CSV/XLSX. Они проверяют даты,
единицы, границу4ч, дубликаты, неизвестную доступность, неполноту, контрольные
суммы, пути и совпадение API/CLI/MCP. Производственные данные в тестах не нужны.
