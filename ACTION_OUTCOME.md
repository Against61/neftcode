# Команды P8/T11/F19 → качество ЛИМС

Этот контур оценивает фактический отклик качества после зарегистрированных
команд. Историческая телеметрия показывает состояние установки, но не содержит
надёжных времён выдачи и исполнения команды. Поэтому `242000_tags.csv` не
подставляется вместо журнала действий.

Без отдельного command log пакет проходит только readiness-аудит: лаг и
коэффициенты не оцениваются, численные значения holdout 2025 не читаются,
2026 остаётся закрытым.

## Журнал команд

Передайте CSV в UTF-8 с точным заголовком:

```csv
command_id,control,issued_time,executed_time,value_before,value_after,unit,status,source_system
```

Одна строка соответствует одной команде. Строки упорядочены по `issued_time`.

| Поле | Контракт |
|---|---|
| `command_id` | Непустой уникальный идентификатор |
| `control` | `P8`, `T11` или `F19` |
| `issued_time` | Время выдачи из журнала оператора/DCS |
| `executed_time` | Подтверждённое время исполнения, не переход телеметрии |
| `value_before`, `value_after` | Уставка до и после исполнения |
| `unit` | `degC` для P8, `t/h` для T11, `MPa` для F19 |
| `status` | `executed`, `cancelled` или `failed` |
| `source_system` | Система, из которой получена запись |

Времена задаются в общей source-local зоне без UTC offset, согласованной с
ЛИМС. Для `cancelled` и `failed` поля исполнения, значений и единицы пустые.
Готовая заготовка: [`examples/command_log_template.csv`](examples/command_log_template.csv).

## Как выполняется оценка

Для выполненной команды origin равен `executed_time`. Событие исключается, если
в пределах ±3 часов исполнена другая команда. Baseline — последняя уникальная
валидная проба серы за 3 часа до origin. После воздействия выбирается отдельная
уникальная проба в каждом окне `(0,1]`, `(1,2]`, `(2,3]` часа. Timestamp ЛИМС
трактуется как reference/sample time; это не время доступности результата
online.

Калибровка допускается при достаточной опоре по каждому control: не менее 20
изолированных исполнений, по 5 в каждом направлении, 10 пар в часовом окне и 3
квартала train. Лаг выбирается на 2023–2024 по leave-one-quarter-out MAE. Затем
фиксируются линейный коэффициент, 90% residual interval и 90% bootstrap interval
коэффициента с поквартальным resampling.

Только после прохождения всех train-gate код читает 2025. Holdout требует не
менее 10 событий на control, улучшение MAE не менее 10% против train-median
baseline и coverage 90% интервала не ниже 80%. Лаги и коэффициенты на holdout не
перенастраиваются. Значения 2026 этот протокол не читает.

Запуск:

```bash
python3 scripts/run_action_outcome.py \
  --command-log /absolute/path/commands.csv \
  --quality-source "/absolute/path/ЛИМСы 01.01.2023 - н.в_ (2).xlsx"
```

Адаптер читает зарегистрированную пару `CQ:CR` прямо из исходной XLSX;
также можно передать подготовленную SQLite или canonical quality CSV из
[`action_collection_v1.json`](configs/action_collection_v1.json). В CSV
`sample_time` остаётся reference time, а пустой `available_time` не разрешает
онлайн-признак. Исходные производственные файлы не
изменяются; каждый запуск
получает frozen code, config, тесты, SHA и audit artifacts.

## Условие подключения ПАК

ПАК остаётся исключённым, пока не подтверждены:

1. смысл timestamp как времени измерения;
2. per-record `available_time` либо доказанная максимальная задержка;
3. источник и допустимые значения health status;
4. источник и допустимые значения calibration status.

Формат метаданных показан в
[`examples/pac_metadata_template.json`](examples/pac_metadata_template.json).
Даже успешно прошедший metadata gate лишь допускает ПАК к отдельной валидации;
он не включает признак автоматически.
